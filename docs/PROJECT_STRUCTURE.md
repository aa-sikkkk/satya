# Satya Project Structure

Authoritative directory map. `AGENTS.md` code map and the `readme.md` tree refer to this file. Layout verified against the codebase-memory graph (1,978 nodes; boundaries scan 2026-10-22).

## Top level

```
Satya/
├── .github/            CI (lint, test matrix, audit), PR/issue templates, bots config
├── ai_model/           LLM inference layer (Phi 1.5 GGUF, CPU-only)
│   └── model_utils/    phi15_handler.py (llama-cpp wrapper), model_handler.py (facade)
├── docs/               All documentation (standards, designs, guides)
├── scripts/            One-time/dev-time tooling (not part of the app runtime)
│   ├── ingest_content.py       Universal content ingestion (entry point)
│   ├── rag_data_preparation/   Chunker + embedding generator (entry points)
│   ├── run_pattern_mining.py   Input-pattern mining (entry point)
│   ├── validation/             validate_standards.py (entry point)
│   ├── load_models_offline.py  Download/caching helper
│   └── release/                Windows bundle build (Nuitka) — off-CI
├── student_app/        Student-facing application
│   ├── main.py                 App entry point
│   ├── interface/              CLI (rich + prompt_toolkit)
│   ├── gui_app/                CustomTkinter GUI (windows, views, assets)
│   ├── learning/               openai_proxy_client.py (optional proxy client)
│   └── progress/               progress_manager.py (JSON progress tracking)
├── system/             Backend libraries (no UI dependencies)
│   ├── rag/            rag_retrieval_engine.py + rag_cache.py (semantic cache)
│   ├── diagrams/       ASCII diagram engine (service/library/renderer/config)
│   ├── input_processing/  Query normalization (4-layer rule-based)
│   ├── data_manager/   content_manager.py (content store)
│   ├── performance/    timeit/resource-usage logging helpers
│   └── security/       input validation utilities
├── teacher_tools/      Content editor CLI (content_editor/, 05 modules)
├── OpenAi_Proxy/       OPTIONAL companion service: OpenAI-compatible proxy
│                        (FastAPI). Needed only when using hosted-LLM fallback.
├── tests/              pytest suite (see conventions below)
├── satya_data/         Runtime data — gitignored (chroma_db/, models/, logs/)
├── textbooks/, notes/  Large content inputs — gitignored (delivered out-of-band)
├── docs/, plan/        plan/ is local-only (git excluded, see AGENTS.md)
├── venv/               Local virtualenv — gitignored
└── _project files_     readme.md, LICENSE, CHANGELOG.md, pyproject.toml,
                        requirements*.txt, AGENTS.md, CLAUDE.md,
                        CODE_OF_CONDUCT.md, release-please-config.json,
                        .release-please-manifest.json, .coderabbit.yaml
```

## Dependency direction (enforced clean)

```
student_app  →  system  →  ai_model
teacher_tools  →  system
OpenAi_Proxy  →  (standalone service; student_app/learning client is separate)
```

- `system/` must not import from `student_app/` (library boundary)
- `ai_model/` knows nothing about `system/rag/` prompt assembly
- zero cycles verified in the call graph; keep it that way (PR checklist)

## Runtime data layout (`satya_data/`, gitignored)

| Path | Purpose |
|---|---|
| `models/phi15/*.gguf` | Phi 1.5 Q4_K_M weights scanned by `model_handler.py` |
| `chroma_db/`, `satya_chroma_db/` | ChromaDB persistent dirs (regenerated by ingestion) |
| `normalization_logs/`, `feedback_db.jsonl` | privacy-relevant student data; stays local |

## Conventions

- Tests: `test_<module>_unit.py` for unit, `test_<module>.py` for integration;
  model-dependent tests carry `@pytest.mark.requires_model` (skipped in CI).
- One markdown per plan in `plan/`; root only holds project-level files.
- Single version source: `pyproject.toml: version` (see `ai_model/__init__.py`).
